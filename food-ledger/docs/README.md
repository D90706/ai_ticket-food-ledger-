## 三份文档的关系

```
qa/build-testcases.py          ← 用例的唯一数据源（123 条）
        │
                        └── docs/测试用例-手工执行版.xlsx  （同一批用例的执行记录表）
```

**用例只在一个地方定义**：`qa/build-testcases.py`。改用例改那一个文件，然后重跑：

```bash
python qa/build-testcases.py      # 重新生成 Excel 执行表
```

不要直接改 `.docx` 或 `.md`——下次重新生成会被覆盖。

## 关于已删除的旧测试文档

项目进入升级阶段后，`docs/测试文档.md` 与 `docs/测试文档.docx` 已删除。原因是它们是**课程设计阶段**的交付物，
而升级阶段的质量要求改由 `docs/升级方案.md` 定义（含"齐但错"的评测集、复核层验收标准）。

用例数据没有丢：**唯一数据源是 `qa/build-testcases.py`**（133 条用例、15 个模块），
执行记录表 `测试用例-手工执行版.xlsx` 仍在。需要恢复旧文档时：

```bash
python qa/build-testcases.py      # 重新生成 Excel 执行表
python qa/build-test-doc.py       # 恢复 docx（已归档）
python qa/build-test-doc-md.py    # 恢复 md（已归档）
```
