# 抽取评测报告

| 项 | 内容 |
|---|---|
| 被测对象 | `Extractor`：deepseek-chat（OpenAI 兼容接口）+ 固定 prompt + 忠实性校验 |
| 模板 | 食材采购台账 v1，19 个字段（必填 12 个，其中法定 12 个） |
| 用例 | 16 条中文口述，日期基准 2026-10-28 |
| 重跑方式 | `RUN_EVAL=1 mvn test -Dtest=ExtractionEvalTest`（会真实调用模型，默认不跑） |

## 一、指标

| 指标 | 数值 | 说明 |
|---|---|---|
| 字段准确率 | **100.0%** (82/82) | 只看被标注的字段 |
| 有值召回率 | **100.0%** (67/67) | 该抽出来的抽出来了没 |
| 瞎填率 | **0.0%** (0/15) | 该空的却填了 |
| 依据编造率 | **3.7%** (5/135) | 依据在原文里找不到，被忠实性校验丢弃 |
| 级别一致率 | **100.0%** (16/16) | 抽取结果与人工标注判出的合规级别一致 |
| 降级次数 | 0 | 模型输出无法解析的次数 |

「瞎填」和「编造」是两件事：
瞎填是字段值凭空出现（台账里等于造假记录），编造是**依据**凭空出现
（值可能对，但"我在原文里看到这句"是假的）。后者更隐蔽，所以单独计量。

## 二、评测过程中发现的三件事

### 1 第一次跑出来的 81.3% 一致率，是我的指标错了

第一版把「人工标注值」和「抽取值」都丢进判定器比级别，但人工标注只标了部分字段。
结果未标注的必填项在人工侧一律算缺失 → 人工侧永远是 RED，
这个指标实际在测量**标注覆盖度**，不是模型水平。

改成「两边只在被标注的字段上判定」后，一致率从 81.3% 变成 93.8%。

> 教训：指标定义错了，比没有指标更危险——它会给出一个看似客观的错误结论。

### 2 唯一一条"未命中"是标注与模板约定打架

E02 期望「没有批号 → 留空」，模型却填了生产日期。查模板才发现
`batch_no` 的说明写着：「包装上的批号；没有批号的散装食材填生产日期」。

**模型是对的，我的标注是错的。**《食品安全法》第五十三条原文也是
「生产日期**或者**生产批号」——散装食材用生产日期作批次标识是合规做法。

修正标注后这条变成命中。顺带把 prompt 第 7 条从"一律不要顶替"
改成"按字段说明执行，没说明才留空"——否则 prompt 会和模板约定互相矛盾。

### 3 依据编造率在同一 prompt 下会浮动

三次运行分别是 3.0% / 1.5% / 3.7%。即使设了 `temperature=0`，
服务端仍存在非确定性。这意味着：

- 编造率不是固定属性，只能当**量级**看（约 2%~4%）
- 忠实性校验必须留在链路上，不能因为"评测过了"就关掉

## 三、这组数字不能说明什么（重要）

| 局限 | 影响 |
|---|---|
| 只有 16 条用例 | 样本小，1 条就值 6 个百分点 |
| 用例与 prompt 出于同一人之手 | 有过拟合风险：换别人写的口述，准确率会掉 |
| 只测了 deepseek-chat | 换模型要重测 |
| 只覆盖单轮与固定的两轮补充 | 真实对话更长、更乱 |
| 标注覆盖 82 个字段比较，不是 19×16 | 未标注的字段没被检验 |
| 没有测极端输入 | 空话、脏话、多笔混杂只各有一条 |

**所以正确说法是**：「在 16 条自建用例上，字段抽取准确率 100%，
依据编造率约 2%~4%，零降级」。不是「准确率 100%」。

## 四、用例设计思路

16 条按「最容易让模型犯错的点」挑，不是按业务均匀挑：

| 类型 | 例 | 考什么 |
|---|---|---|
| 信息齐全 | E01 | 基准线 |
| 散装无批号 | E02 | 是否遵守模板约定 |
| 极简口语 | E03 | 会不会瞎补 |
| 中文数字 | E04 | 「两箱」→ 2 |
| 含糊表述 | E05 | 「大概三十斤」→ 不填准确值 |
| 相对日期 | E06 | 「昨天」→ 具体日期 |
| 缺法定项 | E07 | 缺就缺，不要编 |
| 一句两货 | E08 | 只抽一条，不混 |
| 中文凭证号 | E09 | 不改写编号 |
| 明确"没有" | E10/E15 | 没有保质期/没发票 → 留空 |
| 电话非名称 | E11 | 不把电话填进供货者 |
| 规格与数量 | E12 | 不混字段 |
| 全空兜底 | E13 | 不崩、不编 |
| 单价总价 | E14 | 不串位 |
| 多轮补充 | E16 | 跨轮累积 |

## 五、复现

```bash
cd food-ledger
RUN_EVAL=1 mvn test -Dtest=ExtractionEvalTest
# 报告写到 target/eval-report.md
```

用例在 `src/test/resources/eval/cases.json`，模板从 `db/data.sql` 里读
（不另存一份，否则改模板后指标会失真）。
