## 一、测试模块划分

按**代码边界**划分，不按页面划分——页面上两个按钮可能走同一条后端链路，
而同一个页面里两个功能可能分属完全不同的模块。

| 模块 | 覆盖的代码 | 关注点 |
|---|---|---|
| **M1 登录与权限** | `auth/*`、`WebConfig`、`AuthInterceptor` | 谁能做什么；越权能不能被拦住 |
| **M2 录入与状态机** | `LedgerService`、`LedgerStatus` | 录入正确性、状态只能按规定路线走、并发冲突 |
| **M3 合规判定** | `ComplianceEvaluator` | 红/黄/绿的判定边界、临期与过期的处理 |
| **M4 AI 录入** | `EntryService`、`Extractor`、`LlmClient` | 抽取、追问、确认、溯源、降级 |
| **M5 供应商与证照** | `SupplierService` | 证照到期计算与预警 |
| **M6 查询/分页/导出** | `LedgerService.wrapperOf/page`、`LedgerExportService` | 筛选、分页边界、导出完整性 |
| **M7 统计口径** | `StatsService` | 金额口径、分布自洽 |
| **M8 附件** | `UploadController`、`LedgerValueMapper` | 白名单、静态访问、挂载 |
| **M9 并发与审计** | 乐观锁、`last_actor`、`revision` | 丢更新、责任人、修订号 |
| **M10 前端** | `user/*`、`admin/*` | 手工用例，见第四节 |

## 三、本轮测试发现的 3 个缺陷（均已修复）

### 缺陷 1：修改记录会清空未提交的字段（严重）

- **现象**：用 `PUT /api/ledger/{id}` 只改 `remark`，其余 9 项法定项目全被清空，
  记录从 GREEN 掉成 RED，随后无法入账。
- **原因**：`update()` 走的是整体替换（`apply` 把 null 也写进去）。
- **影响**：任何"只想改一个字段"的调用都会静默抹掉其余数据。台账里这是数据事故。
- **修复**：改为合并语义——请求里为 null 的字段保留原值，要清空请显式传空字符串。
- **回归用例**：TC2-12。

### 缺陷 2：到期日在模板里没有字段，临期预警永不触发

- **现象**：填了到期日，警告却是「未填写到期日，无法做临期预警」。
- **原因**：`expiry_date` 有数据库列、映射器也支持，
  但**模板字段清单里没有它**，于是按模板遍历的映射永远填不进去。
- **影响**：临期/过期预警形同虚设——而这恰恰是食堂检查最常看的一项。
- **修复**：模板补 `expiry_date` 字段（选填，带说明），模板版本 1 → 2。
- **回归用例**：TC3-04、TC3-05。

### 缺陷 3：附件挂不到台账上

- **现象**：上传成功、URL 可访问，但记录的 `attachments` 始终为空。
- **原因**：`LedgerValueMapper` 只遍历模板字段，而 `attachments` 有列但不在模板里，
  于是被当成自定义字段塞进了 `extra_json`。
- **影响**：索证索票照片存了，但和台账记录没有关联，检查时找不到对应凭证。
- **修复**：映射改成按**值的 key** 分发，不再只认模板字段。
- **回归用例**：TC8-04。

> 三个缺陷有同一个共性：**都发生在"有列但不在模板里"或"null 被当成清空"的边界上**。
> 单元测试覆盖不到，只有走完整链路才会暴露——所以接口级回归是必要的，不是重复劳动。

## 五、未覆盖的部分（明确说明）

| 未覆盖 | 原因 |
|---|---|
| 真实并发（两个请求同时到达） | 脚本是串行模拟"旧版本"，没有压测 |
| 大模型输出的稳定性 | 编造率在 2%~4% 之间浮动，见 `docs/eval-report.md` |
| 浏览器兼容性 | 只验证了 Chromium 内核 |
| 权限的更细粒度 | 只有采购员/管理员两种角色，没有按品类或金额分级授权 |
| 上传大文件与畸形文件 | 只验了白名单与正常小文件 |
